# 1. 项目概述

NetworkPlugin 是《LBoL》（东方少女牌梦）的一个 BepInEx 模组，通过 Harmony 补丁和 LiteNetLib 网络库，为原本是单机卡牌游戏的 LBoL 添加完整的多人联机功能。玩家可以组建房间、实时同步战斗状态、交易卡牌/金币/展品、互相治疗、发送聊天消息，并支持中途加入和断线重连。

💡 一句话定义：将 LBoL 从单机卡牌游戏改造为联机合作卡牌游戏的完整网络模组。

🎯 核心价值

让原本只能单人游玩的 LBoL 支持多名玩家同时在线合作闯关，共享地图、战斗、商店等核心游戏体验。

🔑 关键能力

  • 点对点实时状态同步
  • 玩家间卡牌/金币/展品交易
  • 战斗中协作（假死/复活机制）
  • 中途加入进行中的游戏
  • 断线自动重连
  • NAT 穿透与房间管理

📐 技术特点

  • 基于 HarmonyX 的运行时游戏代码 Patch
  • 事件驱动 + 快照同步混合架构
  • 依赖注入（ServiceCollection）
  • 所有 UI 面板完全运行时动态构建

# 2. 背景与目标

2.1 问题背景

LBoL 是一款基于《东方Project》的同人卡牌游戏（类 Slay the Spire），最初仅支持单人离线游玩。玩家社区长期希望引入联机合作模式，但原游戏并未提供任何网络功能。传统的"远程同乐"（Steam Remote Play）方案体验有限，无法实现独立的联机逻辑如交易、协作战斗等。

2.2 产品目标

✅ MVP 目标

  • 实现 2-4 人联机房间
  • 游戏状态实时同步（HP、能量、卡牌、遗物、地图等）
  • 商店/间隙节点玩家间交易
  • 战斗协作（假死救治）
  • 基本聊天功能

📈 增强目标

  • 中途加入进行中的游戏
  • 断线自动重连
  • NAT 穿透（UPnP + STUN）
  • 转生/跨节点传送
  • Mood（心情）系统同步

🚀 远期愿景

  • 观战模式
  • 联机排行榜
  • 自定义规则房间
  • 服务端托管房间（Dedicated Server）

# 3. 用户角色

角色描述核心需求
主机 (Host) 创建并托管房间的玩家 房间管理、权威游戏状态、接收/广播同步数据
加入者 (Joiner) 加入已有房间的玩家 接收同步数据、发送本地操作、保持状态一致
交易者 (Trader) 在商店节点进行玩家间交易 发起/接受交易、选择卡牌/金币/展品、确认交易
救治者 (Medic) 在 Gap 节点治疗阵亡队友 查看可治疗玩家、发起治疗请求
断线重连者 网络断开后重新加入的玩家 获取完整状态快照、恢复到断线前状态

# 5. 模块详解

5.1 Core 核心模块

⚙️ SynchronizationManager

游戏状态同步的核心协调器。管理事件队列 → 网络发送 → 远程事件接收 → 缓冲排序 → 应用。实现 ISynchronizationManager 接口。

DI 单例 事件总线 队列+缓冲

5.2 Network 网络模块

🌐 NetworkClient

基于 LiteNetLib 的网络客户端。管理连接生命周期、事件收发、自动重连、Ping 检测。实现 INetworkClient 接口。

LiteNetLib 自动重连

🖥️ NetworkServer

游戏服务器实现。管理玩家会话、消息路由、房间状态维护。支持中继服务器模式。BaseGameServer + RelayServer 架构。

会话管理 中继模式

🚪 NetworkRoom

房间管理。包括房间创建/加入/退出/列表、过滤、状态同步。RoomSyncManager 驱动房间级状态变化。

房间列表 状态同步

👤 NetworkPlayer

玩家抽象层。本地玩家 (LocalNetworkPlayer) 和远程玩家 (RemoteNetworkPlayer) 统一接口。支持玩家属性同步。

本地/远程 属性同步

📸 Snapshot 快照系统

16 种状态快照模型，用于完整状态同步：FullStateSnapshot, BattleStateSnapshot, CardStateSnapshot, EnemyStateSnapshot, ExhibitStateSnapshot, GameStateSnapshot, LocationSnapshot, MapStateSnapshot, PlayerStateSnapshot, StatusEffectStateSnapshot 等。

全量同步 中途加入 16 种

🔗 MidGameJoin 中途加入

允许玩家在游戏进行中加入。包含 MidGameJoinManager, MapCatchUpOrchestrator, FastSyncService。复杂的校验-批准-快照-执行流程。

复杂流程 断线恢复

🔄 Reconnection 断线重连

自动检测断线 → 后台重试 → 重新获取快照 → 恢复到断线前状态。ReconnectionManager + ReconnectionResult。

自动检测 状态恢复

🔓 NatTraversal NAT 穿透

NAT 类型检测（8 种类型）、UPnP 端口映射、STUN 服务器交互。帮助玩家在复杂网络环境下建立 P2P 连接。

NAT 检测 UPnP STUN

📨 Messages 消息系统

定义 40+ 网络消息类型（NetworkMessageTypes）、消息优先级、序列化/反序列化管道。基于 LiteNetLib 的可靠/不可靠通道。

40+ 类型 优先级

# 7. 用户界面

7.1 UI 设计原则

  • 运行时构建：所有面板不依赖 Unity Prefab，通过 C# 代码在运行时动态创建 UI 元素
  • 复用游戏 UI：通过 Resources.Load + Instantiate 复用游戏内置 UI 元素（MessageDialog、ShowCardsPanel、TMP 模板、按钮模板）
  • 百分比锚点：所有 RectTransform 使用 anchorMin/anchorMax 百分比定位，确保分辨率自适应
  • 本地化友好：通过 TryLocalize() 静默降级，key 缺失时不产生日志噪声

8.4 同步架构

事件驱动 + 快照同步混合架构：常规操作（出牌、伤害、回合切换）通过事件实时同步；中途加入/断线重连时通过快照全量同步。事件使用 SortedList 按时间戳排序缓冲，防止乱序。

8.5 消息优先级

通过 MessagePriorities 定义：

  • Critical (0): 连接/断线、房间操作
  • High (1): 战斗状态、回合切换、玩家 HP 变化
  • Normal (2): 交易、聊天、地图标记
  • Low (3): NAT 探测等后台操作

# 9. 数据模型

9.1 核心模型

🎮 GameEvent

通用游戏事件对象。携带 EventType、UserName、PlayerId、Timestamp、序列化有效负载。通过 GameEventManager 分发。

📦 FullStateSnapshot

全量状态快照。包含 BattleState、PlayerState、MapState、GameState 等子快照。用于中途加入和重连恢复。

🃏 TradeSessionState

交易会话状态。包含 TradeId、PlayerA/B、Offer A/B（CardRef[]）、Money A/B、Exhibits A/B、Status、Reason。通过 TradeSyncPatch 同步。

🧟 DeathEntry / DeathRegistry

死亡登记。记录死亡玩家的 PlayerId、Hp、位置。DeathRegistry 管理全局死亡列表，ResurrectPanel 读取。

👤 DeadPlayerEntry

治疗面板中用于展示的玩家条目。包含 PlayerId、PlayerName、CurrentHp、MaxHp、CanResurrect、ActionValue、ResurrectionCost。

🏠 NetworkRoom

房间模型。包含 RoomId、HostId、PlayerList、RoomConfig、RoomStatus、Filter 标签。

9.2 SyncVar 同步变量

SyncVar<T> 是一个泛型可观察变量，值变化时触发 OnValueChanged 事件，在服务端用于自动网络推送，在客户端用于触发 UI 更新。

9.3 TradeExhibitRules

展品交易规则引擎，定义哪些展品可交易、哪些在黑名单。通过 IsTradable() 和 IsBlacklisted() 校验。
