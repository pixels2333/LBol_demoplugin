双服务器模式

NetworkServer（房主直连）：由房主启动，管理玩家会话与游戏事件广播，适用于已知 IP 的局域网或小范围联机。

RelayServer（中继）：独立部署，提供房间管理、NAT 穿透协调、消息中转，适用于公网跨 NAT 场景。底层核心均为 BaseGameServer + IServerCore。

核心设计原则
  • 主机权威（Host Authority）：战斗状态、快照、追赶数据由主机生成并广播。
  • ReliableOrdered UDP：基于 LiteNetLib，保证消息有序到达，兼顾低延迟与可靠性。
  • JSON 序列化：跨平台兼容，便于调试与版本演进。
  • Harmony 补丁注入：通过 28+ 个 SyncPatch 在不改动游戏源码的情况下拦截并同步游戏状态。
  • 快照裁剪：FullSnapshot 用于中途加入/追赶，Delta 用于常态同步。

SyncVar<T> 泛型同步

包装任意类型值，通过 EqualityComparer<T>.Default.Equals 检测变更。值改变后触发 OnValueChanged 事件，服务端用于触发网络发送，客户端用于 UI 更新。

SyncVar<int> Mana = new("Mana", 3);
Mana.Value = 2; // 自动触发网络同步
Snapshot 快照体系

按粒度分为多级快照：

  • FullStateSnapshot：完整游戏状态，用于中途加入/重连追赶。
  • BattleStateSnapshot：战斗场景全量（玩家/敌人/意图/卡牌/能量）。
  • MapStateSnapshot：地图节点、路径、检查点。
  • PlayerStateSnapshot：玩家 HP、Mana、Block、StatusEffects。
  • TurnBoundarySnapshot：回合开始/结束边界状态。

创建房间

客户端发送 CreateRoom 请求至 RelayServer。服务器校验后创建 NetworkRoom 实例，分配 RoomId，首个加入者自动成为房主（HostPlayerId）。返回 RoomCreated 响应。

加入房间

客户端发送 JoinRoom（携带 RoomId 与可选密码）。NetworkRoom.AddPlayer 进行容量与重复加入检测。成功后广播 PlayerJoined 与 PlayerListUpdate。

房主权限

房主拥有唯一权限：踢出玩家（KickPlayer）、修改房间配置（如提升容量）、发起开局。房主离开后，按加入顺序自动迁移至下一位玩家。

房间配置

RoomConfig 包含：最大人数、密码、游戏模式、是否允许中途加入等。开局后 IsInGame = true，禁止新玩家加入（除非启用中途加入）。

开局同步

房主触发开局后，服务器广播 HostChanged 确认房主身份，随后进入游戏初始化。主机生成 GameRun 与种子（Seed），通过 RoomSyncManager 广播初始地图状态。

检查点（Checkpoint）

地图推进时生成 MapCheckpoint，用于中途加入玩家的追赶锚点。检查点包含节点 ID、种子校验、路径历史，保证后加入者能重建相同地图拓扑。

房间内广播

游戏事件通过 RoomMessage 或 DirectMessage 在房间内流转。RelayServer 负责按房间 ID 过滤，仅转发给同房间成员，避免跨房间泄露。

地图推进同步

玩家进入新节点时，RoomEntrySyncPatch 与 MapCheckpointSyncPatch 同步节点选择与检查点。所有客户端收到后更新本地地图视图，保持房间进度一致。

正常离房

客户端发送 LeaveRoom，服务器从 NetworkRoom._players 移除该玩家，广播 PlayerLeft。若离房者为房主，触发 HostChanged 迁移房主。

异常断线

心跳超时（默认 5s 间隔，30s 超时）后服务器标记断线，保留会话 60 秒（ReconnectGracePeriod）。断线期间不触发 AI 接管，玩家可通过 Reconnect_REQUEST + Token 恢复。

wifi_tethering 断线重连与中途加入
可靠性设计：快照保存、重连令牌、地图追赶
ReconnectionManager 机制
  • 心跳监控：客户端每 5s 发送 Heartbeat，服务端记录时间戳。
  • 超时判定：超过 DefaultNetworkTimeoutSeconds（30s）未收到心跳即判定断线。
  • 快照保存：断线时主机生成 PlayerStateSnapshot 存入 _playerSnapshots 字典。
  • 事件历史：最近游戏事件按时间戳存入 SortedList<long, GameEvent>，用于追赶。
  • 重连令牌：断线时服务端生成 GUID Token，60s 内客户端携带 Token 可恢复原有 PlayerId。
  • 最大尝试：默认最多 5 次重连尝试，间隔 5s。
MapCatchUpOrchestrator 地图追赶
  • FullStateSnapshot 接收：加入者首先接收主机的完整状态快照（重点是 MapStateSnapshot）。
  • 暂存机制：若本地 GameRun 尚未就绪，快照暂存于 _pendingSnapshot，由 PumpMainThread 周期性轮询。
  • 种子校验：对比本地与主机 Seed，不匹配时记录警告（5s 节流去重）。
  • 路径重建：按 CheckpointId 与路径历史逐步恢复已访问节点。
  • 房间状态请求：地图应用完成后，通过 RoomSyncManager 请求当前房间状态，避免重复请求同一检查点。
时序示意：断线 → 重连 → 追赶
服务端：心跳超时检测到 PlayerA 断线 → 保存 PlayerStateSnapshot + 生成 ReconnectToken → 开始 60s 优雅期倒计时

PlayerA：检测到断线，进入重连循环（最多 5 次，间隔 5s） → 发送 Reconnect_REQUEST（携带 Token） → Token 校验通过 → 恢复原有 PlayerId 与会话 → 发送 FullStateSnapshot + 事件历史 → MapCatchUpOrchestrator 应用快照与追赶
